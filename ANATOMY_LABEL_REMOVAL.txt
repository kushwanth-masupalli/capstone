WHY REMOVING ANATOMY LABELS IS SAFE
====================================

Decision: ANATOMY_LABELS = [] (empty). The classifier trains only on the 7
pathology labels. This document explains why this is safe and why it has no
effect on LLM report generation.


1. WHAT THE ANATOMY LABELS WERE
-------------------------------
Anatomy labels (Spine, Lung, Aorta, Diaphragm, ...) came from the MeSH
column of indiana_reports.csv. The MeSH format is "anatomy-site / descriptor"
(e.g. "Spine/degenerative/mild"). The ORIGINAL pipeline kept only the first
token, discarding the descriptor, leaving bare anatomy terms like "Spine".

Bare anatomy labels carry almost no clinical information:
  - Every chest X-ray contains a spine, lungs, aorta, diaphragm. The label
    "Spine" only meant "the radiologist mentioned the spine" - not what was
    wrong with it.
  - The real finding lived in the discarded descriptor
    ("Spine/degenerative" = degenerative change; "Lung/hypoinflation" =
    hypoinflation). Stripping to the first token threw the finding away.
  - These terms are not diseases. A findings classifier that predicts
    "Lung" or "Spine" produces clinically meaningless output.


2. WHY REMOVING THEM IS SAFE FOR CLASSIFIER TRAINING
----------------------------------------------------
a) They hurt training, they never helped it.
   The old 15-label run (which included "normal", Spine, Lung, Aorta,
   Diaphragm, Markings, Density, Catheters) achieved val micro-F1 = 0.387,
   macro-F1 = 0.229, and AUC ~0.48 (near random). The bare anatomy and
   noise labels dragged the model down: they are anti-correlated with real
   findings and cannot be learned meaningfully.

b) The recovered pathology labels keep the useful half.
   The cleanup (recover_mesh_term in dataset.py) maps:
       "Spine - degenerative"      -> Degenerative Spine Disease
       "Lung - hypoinflation"      -> Pulmonary Hypoinflation
       "Lung - hyperdistention"    -> Pulmonary Hyperinflation
   So the anatomy term survives INSIDE the pathology label as a descriptor.
   No clinical signal is lost - it is just attached to a real, reportable
   disease instead of a bare body part.

c) The anatomy head no longer exists in the model.
   train.py builds the anatomy head only `if n_anatomy > 0`; with
   ANATOMY_LABELS = [] the model outputs only the 7 pathology logits.
   Nothing downstream can read anatomy output because there is none.

d) Downstream consumers expect pathology-only.
   - src/pseudo/generate_pseudo_labels.py asserts label_names ==
     PATHOLOGY_LABELS and refuses to run otherwise.
   - Checkpoints store n_pathology; evaluation and the demo iterate the
     pathology label list only.


3. WHY IT DOES NOT AFFECT LLM REPORT GENERATION
-----------------------------------------------
The LLM report generator NEVER consumes the label vectors. The report is
built from different data entirely (per PLAN.md Phases 5-7):

   Inputs to report generation:
     - the X-ray image
     - retrieved prior cases + guidelines (the RAG corpus)
     - patient history
     - the classifier's predicted pathology FINDINGS (as the retrieval
       query and hallucination cross-check)

   Data source of the report text itself:
     indiana_reports.csv columns: uid, MeSH, Problems, image, indication,
     comparison, findings, impression.

Therefore:

a) No report text is lost. All anatomy context lives in the free-text
   `findings` and `impression` columns ("mild degenerative changes of the
   thoracic spine", "granuloma in the left upper lobe", "heart is normal
   in size", ...). Removing ANATOMY_LABELS does not touch these columns.

b) The raw MeSH column is still on disk. The full anatomy-qualifier terms
   (Spine/degenerative, Lung/hypoinflation) remain parseable if location or
   laterality metadata is ever needed. ANATOMY_LABELS = [] only stops the
   CLASSIFIER from being forced to predict them.

c) The retrieval corpus is report TEXT, not labels. Chunks of real reports
   + guideline text are unchanged by the label list.

d) Hallucination detection cross-checks extracted findings against the
   classifier's pathology predictions. It was always pathology-driven;
   anatomy labels were never part of that comparison.

What is actually removed: a few 0/1 columns in the classifier's training
matrix that were noise, were never consumed by the LLM, and degraded
classifier quality.


4. SUMMARY
----------
- Anatomy labels were uninformative classifier targets derived from a lossy
  parse of MeSH.
- Removing them improves classifier training (no noise targets, no dominant
  bare-anatomy classes).
- The anatomy knowledge the LLM needs survives in the free-text reports,
  where it always lived.
- No data is deleted, nothing is lost for report generation.
